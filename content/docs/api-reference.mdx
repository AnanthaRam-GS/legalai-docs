The backend is a single FastAPI application. All requests and responses are JSON, except PDF uploads, which use `multipart/form-data`. Sessions use an HttpOnly cookie, so browser clients send requests with credentials included.

**Roles:** _Anyone_ needs no account. _Signed in_ means any authenticated user. _Lawyer_ covers the `lawyer` and `admin` roles. _Admin_ is `admin` only. The role is always read from the database, never from the client.

## Authentication

| Method | Path                        | Role      | Purpose                                              |
| ------ | --------------------------- | --------- | ---------------------------------------------------- |
| POST   | `/auth/register`            | Anyone    | Create a `public` account and email a six-digit code |
| POST   | `/auth/verify-email`        | Anyone    | Verify the email with the code                       |
| POST   | `/auth/resend-verification` | Anyone    | Send a new code (same answer for every email)        |
| POST   | `/auth/login`               | Anyone    | Email and password; sets the session cookie          |
| POST   | `/auth/logout`              | Anyone    | Clears the session cookie                            |
| GET    | `/auth/me`                  | Signed in | The current user and role                            |

Registration, resend and verification answer identically whether or not the email has an account, so they cannot be used to discover accounts.

## Queries

| Method | Path                      | Role   | Body                                       | Response                    |
| ------ | ------------------------- | ------ | ------------------------------------------ | --------------------------- |
| POST   | `/query/public`           | Anyone | `{ "text": "…" }`                          | `PublicQueryResponse`       |
| POST   | `/query/public/pdf`       | Anyone | form: `query`, `file` (PDF)                | `PublicQueryResponse`       |
| POST   | `/query/professional`     | Lawyer | `{ "text": "…", "session_id"?: "…" }`      | `ProfessionalQueryResponse` |
| POST   | `/query/professional/pdf` | Lawyer | form: `query`, `file` (PDF), `session_id`? | `ProfessionalQueryResponse` |

- **Public responses** contain a plain-language explanation, the sections cited, sources (validated citations only) and `limitations`, such as an OCR confidence warning.
- **Professional responses** contain identified sections, `precedents` (one per retrieved judgment, in rank order, with provenance, a verbatim excerpt, the raw reranker score, relative relevance and `cited_in_answer`) and a structured `case_brief`.
- Uploaded PDFs are used for that request only and are never added to the corpus.
- Public routes are limited per client IP (5 a minute, 100 a day by default) and professional routes per user (10 a minute, 300 a day).

## Corpus ingestion

| Method | Path                      | Role  | Purpose                                                                                |
| ------ | ------------------------- | ----- | -------------------------------------------------------------------------------------- |
| POST   | `/ingest/upload`          | Admin | Upload a trusted PDF with metadata; returns a persistent job ID                        |
| GET    | `/ingest/status/{job_id}` | Admin | Stage, progress, chunk count, error code and `needs_reconciliation`                    |

## Analytics

All analytics endpoints require the Lawyer role and return `200 []` when there is no data.

| Method | Path                              | Purpose                                               |
| ------ | --------------------------------- | ----------------------------------------------------- |
| GET    | `/analytics/offense-frequency`    | Offence citations by section and judgment year        |
| GET    | `/analytics/outcome-distribution` | Outcomes by section and court level                   |
| GET    | `/analytics/section-cooccurrence` | Pairs of offence sections cited together              |
| GET    | `/analytics/ipc-bns-map`          | IPC-to-BNS mapping rows                               |
| GET    | `/analytics/ncrb-stats`           | NCRB Table 1A.4 rows by year, State/UT and crime head |

- Section labels are statute-qualified, such as `IPC 302` or `BNS 103`.
- The first three count offence provisions only; `include_all_sections=true` returns every cited section.
- `ncrb-stats` leaves out total and subtotal rows unless `include_aggregates=true`, so sums do not double count. Its `ipc_section` filter accepts `IPC 305`, `BNS 108` or a bare `305`.
- Aliases `/analytics/offence-frequency`, `/analytics/ipc-bns` and `/analytics/ncrb` return the same data.

## Error format

Every error response, from any route, middleware or the framework, has the same body:

```json
{
  "error": "Some of the submitted information is missing or invalid.",
  "code": "VALIDATION_ERROR",
  "detail": {
    "fields": [{ "field": "body.email", "message": "Field required", "type": "missing" }]
  }
}
```

- `error` is a safe, human-readable message. It never contains a stack trace, a file path or a submitted value.
- `code` is stable; clients branch on `code`, never on `error`.
- `detail` holds structured data for some codes, otherwise `null`.
- Every response carries an `X-Request-ID` header, and a `500` returns the request ID in `detail` so it can be matched to the server log.
